# Box orientation: reference methods and a correction plan

Reviewed 2026-11-05. Scope: offline camera-mask + LiDAR vehicle labels, especially slightly incorrect box yaw. This is reference research and an implementation plan; no production behavior changed. Read alongside [the prior SLF review](slf_projection_implementation_review.md), whose corrected paper definitions still apply.

Status: plan step 4 (fit yaw with the shape) and part of step 3 (a gated velocity heading) are implemented; measurements in the "Heading" section of [label_refinement_measurements.md](../label_refinement_measurements.md). The local comparisons below were run with diagnostic scripts that aren't in the repository.

## What SLF actually optimizes

**Segment, Lift and Fit (Li et al., ECCV 2024)** optimizes pose `(x, y, z, yaw)` jointly with a **five-dimensional PCA SDF shape**. Its car prior uses 79 Apollo-Car3D models. Roll and pitch are omitted. This PCA describes *shape variation*, not principal-axis yaw fitting of observed LiDAR. The objective combines occlusion-aware mask Dice, LiDAR surface alignment including the first camera-ray intersection, and a ground penalty. The final optimization paragraph initializes position from median frustum points and shape from the mean; an earlier paragraph says random initialization. The paper does not specify a reproducible yaw initialization in comparable detail. It is a **single-image / single-point-cloud method**, not a temporal trajectory fitter. Sparse returns can confuse front and rear; Table 3 reports orientation errors 0.836 rad with directed yaw and 0.113 rad modulo π. [Proceedings PDF, §§3.2–3.4, 4.2](https://www.ecva.net/papers/eccv_2024/papers_ECCV/papers/11297.pdf)

The current repository fits a rounded box with Phase 3 heading fixed: `slf.py` constructs constant sine/cosine tensors from `Problem.heading`. Therefore its mask and point losses cannot repair yaw. Freeing yaw restores a paper optimization variable, but retaining rounded boxes and track-level sharing remains an adaptation, not a faithful reproduction of SLF's shape model. [Local implementation](../../src/label_refinement/src/wato_label_refinement/slf.py)

No author implementation was located through the paper, author publication page, and targeted repository searches. The author's SLF entry currently links only the paper. This is a bounded search result, not proof that no code exists. [Author page](https://provemj.github.io/)

## Geometry seeds: L-shape / edge closeness, minimum area, and PCA

Zhang et al.'s **Efficient L-Shape Fitting** searches rectangle orientation over a quarter turn, projects points onto two perpendicular axes, and compares area, edge-closeness, or edge-variance criteria. Closeness rewards returns lying near rectangle edges using a distance floor. It encodes visible surface structure; area minimizes enclosure size. The paper allows tracking or vision to restrict the search. It does not supply directed front/rear evidence. [Author-hosted paper, Algorithms 2–5](https://www.ri.cmu.edu/app/uploads/2017/07/Xiao-2017-Efficient-L-Shape-Fitting.pdf)

**MODEST has inspectable official source**, pinned here to `1c088fd9e65b3e4a62d988009016d1262d95dc81`:

- `closeness_rectangle` searches in **0.1°** increments by default, computes the enclosing rectangle for each angle, then maximizes `sum(1 / max(nearest_edge_distance, 0.01 m))`. It swaps axes when necessary to return the longer axis as heading. Its endpoint grid includes 90°. [Function](https://github.com/YurongYou/MODEST/blob/1c088fd9e65b3e4a62d988009016d1262d95dc81/generate_cluster_mask/utils/pointcloud_utils.py#L167-L216)
- The official generation config selects `bbox_gen.fit_method: closeness_to_edge`, and generation passes that option to `get_obj`. Thus closeness is an active reference path, not merely an unused utility. [Config](https://github.com/YurongYou/MODEST/blob/1c088fd9e65b3e4a62d988009016d1262d95dc81/generate_cluster_mask/configs/generate_mask.yaml), [Caller](https://github.com/YurongYou/MODEST/blob/1c088fd9e65b3e4a62d988009016d1262d95dc81/generate_cluster_mask/generate_mask.py#L93-L94)
- The same source separately implements PCA and convex-hull minimum-area rectangles. PCA fits eigenvectors of the observed return distribution. Consequently, uneven visibility/density can rotate its axes even when the physical vehicle axes have not changed; that consequence follows from the objective, rather than being a claim of guaranteed failure. [Implementations](https://github.com/YurongYou/MODEST/blob/1c088fd9e65b3e4a62d988009016d1262d95dc81/generate_cluster_mask/utils/pointcloud_utils.py#L88-L165)

MODEST's wider pipeline uses cross-traversal persistence to discover mobile objects. Its rectangle fitting can be studied independently; adopting it does not require adopting the repeated-traversal discovery stage. [Official repository](https://github.com/YurongYou/MODEST)

**Local comparison, not a dataset result:** the exact MODEST closeness function returned 0° on the three points `(-2.25,-0.9), (2.25,-0.9), (-2.25,0.9)`, both before and after adding `(2.45,-0.5)`, using 0.1° and 5° grids. It also returned 0° for a densely sampled L plus that point. The separate current-repository minimum-area probe returned −16.587° after adding the point. The sparse closeness case has score ties because every point can lie on a boundary; this result motivates a controlled comparison, not a claim of universal robustness.

**Real cached-track replay:** for parked truck track `0000-54` in `NuScenes_v1_0_mini_scene_0061_0_mcap`, the repository's gathering/filtering/voxel/group path accumulated 25,172 points over 264 frames. On those identical points, axial yaw error was **14.4307° for minimum area**, **14.4170° for exact MODEST closeness at 0.1°**, and **13.3170° for the 5° grid**. Changing the criterion alone does not repair this case. Point selection, aggregation, yaw/shape coupling, and image evidence must be investigated; this replay alone does not distinguish their contributions.

## Temporal heading: verified LISO implementation

**LISO (Baur et al., ECCV 2024)** mines moving objects from ego-compensated scene flow, tracks them, smooths trajectories, aligns yaw with the smoothed path, then trains a detector that can generalize to stationary movable objects. It shares dimensions across each track using an observed-dimension percentile. These are motion-based pseudo-labels and self-training, not image-mask fitting. [Paper, §§3.1–3.3](https://arxiv.org/html/2403.07071v1)

Official code is available at `baurst/liso`, inspected at `e4143744dceaa1e73c959f38f4827d3e9bbc21b3`:

| Code path | Verified behavior |
| --- | --- |
| Initial moving-object yaw | Current release forms BEV regions, then estimates per-object and background rigid transforms from flow. The object's residual translation determines a yaw correction through `atan2`. Do not describe this current implementation as deriving every yaw from an L-shaped rectangle. [Flow detector](https://github.com/baurst/liso/blob/e4143744dceaa1e73c959f38f4827d3e9bbc21b3/liso/networks/flow_cluster_detector/flow_cluster_detector.py#L311-L331) |
| Point rectangle fit | `box_fitting.py` explicitly credits MODEST and contains the same closeness criterion, but changes the default angular step to **5°**. [Function](https://github.com/baurst/liso/blob/e4143744dceaa1e73c959f38f4827d3e9bbc21b3/liso/box_fitting/box_fitting.py#L93-L142) |
| Local fitting controls | Track refinement calls closeness fitting, but default `fit_rot: False`, `fit_pos: True` uses it to change centers while preserving yaw. The existence of a fitter does not imply it controls the exported heading. [Caller](https://github.com/baurst/liso/blob/e4143744dceaa1e73c959f38f4827d3e9bbc21b3/liso/tracker/tracking.py#L2044-L2083), [Config](https://github.com/baurst/liso/blob/e4143744dceaa1e73c959f38f4827d3e9bbc21b3/liso/config/liso_config.yml#L29-L39) |
| Path smoothing | `smooth_track_jerk` minimizes third finite differences of positions plus weighted squared deviation from observed centers (default weight 3). Yaw parameters appear in the module, but the active smoothing loss does not optimize them. [Third differences](https://github.com/baurst/liso/blob/e4143744dceaa1e73c959f38f4827d3e9bbc21b3/liso/tracker/track_smoothing.py#L77-L84), [Loss](https://github.com/baurst/liso/blob/e4143744dceaa1e73c959f38f4827d3e9bbc21b3/liso/tracker/track_smoothing.py#L147-L182) |
| Heading after smoothing | It replaces yaw with the path tangent only where displacement is **greater than 1 m**. It expands the frame separation from 1 up to `min(10, N//2)`. Unresolved interiors retain observed yaw; the first and last valid yaw copy their neighbor. `atan2` uses XY displacement. [Gate and replacement](https://github.com/baurst/liso/blob/e4143744dceaa1e73c959f38f4827d3e9bbc21b3/liso/tracker/track_smoothing.py#L219-L290), [Tangent](https://github.com/baurst/liso/blob/e4143744dceaa1e73c959f38f4827d3e9bbc21b3/liso/tracker/track_smoothing.py#L460-L486) |

There is also an outer travel gate: `tracking.py` reads `tracking_cfg.min_dist_for_track_smoothing` with default **5 m**. The inspected default YAML places **3 m under `tracking_cfg.flow_tracker`**, a different path. Therefore the YAML alone does not establish that 3 m is active. Tracks also need adequate age. This discrepancy should be preserved in any reproduction record, not silently turned into a recommended WATO threshold. [Outer gate](https://github.com/baurst/liso/blob/e4143744dceaa1e73c959f38f4827d3e9bbc21b3/liso/tracker/tracking.py#L1188-L1206), [YAML](https://github.com/baurst/liso/blob/e4143744dceaa1e73c959f38f4827d3e9bbc21b3/liso/config/liso_config.yml#L35-L42)

The paper HTML's displayed fourth derivative for “jerk” disagrees with both its wording and the released third-difference code. Use the inspected code for an implementation comparison.

## What the other temporal methods actually contribute

**OYSTER (CVPR 2023):** seeds come from ground removal, clustering, and L-shape-based tight box fitting. Bidirectional tracking rejects short tracks. Refinement chooses a high percentile of track dimensions and grows each box around its corner nearest the ego vehicle, explicitly **retaining the original heading**. It does not provide a temporal yaw correction in that refinement step; it even reports that size growth with inaccurate heading can degrade distance-to-collision metrics. [Paper, §3.2 and Appendix A](https://arxiv.org/html/2311.02007v1). No official implementation was located from the linked author project page or targeted searches; the page currently links paper, supplementary material, and video. [Author project](https://waabi.ai/research/oyster)

**Auto4D (2021):** a supervised two-branch refinement model predicts one size for a vehicle track and refines its `(x,y,yaw)` path using both LiDAR and temporal state features. For the size branch it crops enlarged boxes, transforms their points to object coordinates using the input poses, and aggregates there. For the path branch it keeps time-coded observations in world coordinates. It predicts yaw corrections; it does not simply set yaw equal to velocity direction. With accurate ego poses, static-object size estimation can instead aggregate in world coordinates to avoid initial box-pose noise. [Paper, §§III-B–III-D](https://arxiv.org/html/2101.06586v2). No author implementation was identified in this review.

**3DAL / Offboard 3D Object Detection (CVPR 2021):** a supervised static branch merges object observations in world coordinates and produces one box. The dynamic branch consumes short time-coded point sequences and longer box sequences around a target frame. It deliberately avoids explicitly registering moving points to the target frame because sparse/occluded-object registration can be harder than box estimation. Thus it is incorrect to attribute mandatory object ICP to 3DAL. [Paper, §§4.3–4.4](https://arxiv.org/html/2103.05073v1). The discoverable [3DAL_PyTorch repository](https://github.com/jacky121298/3DAL_PyTorch) is a separate reimplementation that substitutes CenterPoint and Frustum PointNets, not the authors' original code. No author implementation was located.

**FGR (ICRA 2021):** an official geometric alternative exists. Its released code scans yaw at 0.5° and favors points near the bounding rectangle boundary by minimizing the fraction inside a shrunken rectangle; it then selects a key vertex and uses frustum geometry to estimate full extent. This is a different criterion from reciprocal-distance closeness. Its image-box assumptions require care when substituting ordinary modal masks. [Official code, pinned `3f794feb9f5aa294057ccfa6fbf49e2dc5d02d07`](https://github.com/weiyithu/FGR/blob/3f794feb9f5aa294057ccfa6fbf49e2dc5d02d07/FGR/detect.py#L35-L100), [Official README](https://github.com/weiyithu/FGR)

## Plan for this repository

The following is a proposed adaptation informed by the references, not an algorithm claimed verbatim by one paper:

1. **Diagnose yaw by stage and motion state.** For the same owned track instants, compare lifting, fused proposals, tracking output, Phase 3, and fitted boxes against available GT/BEV overlays. Report axial yaw error modulo π separately from directed yaw modulo 2π. Check center drift, point contamination, observation count, pose timing, and camera calibration before assigning a cause to a real track.
2. **Benchmark source-faithful seeds and audit their points.** Implement the pinned MODEST closeness criterion as a candidate alongside the existing minimum-area fit and PCA. Use observed points from the same masks/tracks, and record yaw-score ambiguity. Compare per-frame geometry against the parked world aggregate, examine residuals/contamination by frame and camera, and test whether the retained component describes the intended object surfaces. Preserve multiple plausible axial candidates when evidence is weak; the original closeness score is neither outlier-proof nor a statistical confidence estimate. The real parked-truck replay already shows that a criterion-only swap is insufficient.
3. **Use motion as a gated prior.** Following LISO, derive path orientation from a smoothed world-coordinate track over sufficient displacement, expanding the baseline for slow objects. Benchmark thresholds on representative tracks. Treat short, stopped, turning, reversing, and center-drifting tracks explicitly. A stationary trajectory has no defined velocity heading; reverse motion determines travel direction but does not alone determine which end is the vehicle front.
4. **Optimize yaw against mask and LiDAR evidence.** Restore yaw as an optimization variable, with one constant world yaw for confidently parked rigid tracks and per-frame yaw plus a confidence-weighted temporal prior for moving tracks. Keep one size/shape per rigid track. Evaluate axial seeds and preserve uncertainty where their losses are indistinguishable. A temporal extension of SLF must be documented as such.
5. **Aggregate in the appropriate coordinates.** A parked rigid object can combine world-aligned observations using trusted ego poses. A moving rigid object requires an object transform to remove both translation and rotation before canonical shape accumulation: `q_i = R_i.T @ (p_world_i - c_i)`. Translation-only alignment smears a turning vehicle. This transform is geometry, not a claim that 3DAL performs object registration. Assess registration residuals and avoid allowing bad initial box poses to fabricate a confident shape.
6. **Validate on held-out tracks.** Include parked, straight-moving, turning, stopping, reversing, sparse, occluded, multi-camera, and chunk-seam cases. Compare orientation, center, dimensions, BEV/3D IoU, temporal jitter, and per-camera mask alignment. Preserve the fitter's evaluated pose in export; do not smooth or re-anchor it afterward without re-evaluating the evidence.

Still unknown: how broadly the observed failures occur across WATO recordings; whether geometry seeds, changing visible surfaces, center drift, pose/calibration, or loss ambiguity dominate each track's yaw error; whether full SLF shape priors would outperform the rounded-box adaptation here; and whether object-level registration is reliable at this rig's return densities. No threshold or production change is justified solely by the synthetic probe.
