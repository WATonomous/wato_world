# The Dockerfile asked for `torch>=2.7,<3`, which floated to 2.11.0. Two
# consequences, both locked in below because this set is what currently works:
#
#   1. `cuda-toolkit==12.8.1` is pulled in. torch 2.10+ added a runtime dep on
#      that multi-GB PyPI meta-wheel. docker/perception_2d.Dockerfile pins
#      torch==2.7.1 *specifically to avoid it* — the base image already ships
#      the CUDA 12.8.1 runtime + cuDNN, so the meta-wheel is redundant bulk.
#
#   2. This component and perception_2d are on different torch builds
#      (2.11.0 / cuDNN 9.19.0 / NCCL 2.28.9 here, vs 2.7.1 / cuDNN 9.7.1 /
#      NCCL 2.26.2 there). Nothing shares tensors across the two images today,
#      so this is not a correctness bug, but it doubles the CUDA wheel
#      footprint on disk and means a kernel-level bug reproduces in one
#      component and not the other.
#
# Aligning both components on one torch means rebuilding and re-validating
# lidar_preprocessing (numba kernels, pypatchworkpp, open3d) — a separate,
# testable change. Until then this lock at least makes the drift explicit and
# frozen instead of silent and moving.
#
# INDEX RESOLUTION
# ----------------
# Installed with `--index-strategy unsafe-first-match`. uv's default strategy
# considers only the FIRST index that carries a given package name, which
# breaks here: download.pytorch.org/whl/cu128 mirrors common packages like
# certifi at its own versions, so the default strategy refuses to fall back to
# PyPI for them and the install fails to resolve. unsafe-first-match walks the
# indexes in order and takes the first that has the *requested version* — PyPI
# for ordinary packages, the cu128 index only for the wheels PyPI lacks
# (torch==...+cu128 and friends).
#
# The "unsafe" in the name refers to dependency confusion, where an attacker
# publishes a same-named package on another index. That risk is much reduced
# here: every version is exactly pinned and installed with --no-deps, so a
# hostile index cannot introduce a package or a version this file does not
# already name. Both indexes are also first-party (PyPI, pytorch.org).
